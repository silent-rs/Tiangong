# tiangong-memory-consolidator

记忆深度整理**独立工具**。对天工 Memory 的长期记忆库做一次全量「深刻整理」：
合并高度一致的记忆、重新归纳分类、重建关联链，并遗忘低质量记忆。

本工具是独立制品：只通过 `tiangong-memory` 的公开 API 读写记忆，**不修改
Memory 插件本身的任何代码**；接入方式与 `tiangong-memory-sidecar` 的通用模式
一致（竞争 Leader，天工运行时以 Follower 经 IPC 转发），因此天工正在使用时
也可以安全运行，记忆数据始终只有一份。

## 使用

只需要指定天工根目录，工具会自动识别 Memory 系统配置的模型
（LLM / Embedding / Rerank）：

```bash
cargo run -p tiangong-memory-consolidator -- --root ~/.tiangong
```

常用参数：

| 参数 | 说明 | 缺省 |
|---|---|---|
| `--root <目录>` | 天工根目录（存储根）；也可用环境变量 `TIANGONG_STORAGE_ROOT` | `~/.tiangong` |
| `--threshold <0~1>` | 相似度阈值，越高越保守 | `0.90` |
| `--group-limit <n>` | 每组最多参与的相似记忆数 | `6` |
| `--candidate-limit <n>` | 每条记忆的相似候选检索数 | `12` |
| `--max-nodes <n>` | 单批最多处理多少条记忆，`0` 表示不限 | `0` |
| `--offset <n>` | 跳过最新的 N 条再开始（断点续跑） | `0` |
| `--dry-run` | 试运行：只报告不落库（仍会调用 LLM 生成预览决策） | 关 |
| `--keep-low-quality` | 保留低质量记忆，不执行遗忘 | 关 |

建议第一次先用 `--dry-run` 预览将要发生的合并与遗忘，确认后再正式执行。

## 整理逻辑

1. **获取所有记忆**：全库分批拉取活跃记忆——每批最多 5000 条（按更新时间
   从新到旧），整理完自动取下一批，直到某批不足 5000 条即全库整理完成；
   记忆库很大时可用 `--offset` 断点续跑。
2. **逐条向量检索**：配置了 Embedding 端点时，本地批量计算向量与余弦相似度
   （字符二元组预过滤，避免全量两两比较）；未配置时退化为「经 Memory 召回
   取候选 + 字符二元组 Jaccard 判定」。相似度达到阈值的记忆构成一个「高度
   一致组」。
3. **LLM 归一与分类**：把一致组交给 Memory 配置的 LLM，产出合并后的
   标题/摘要/关键词/认知分类/重要性，并给出低质量遗忘清单与新的关联链；
   LLM 不可用或输出不合法时退化为规则整理（保留信息最完整的一条，其余归档）。
4. **关联链重建**：已归档记忆的关系被重指向主记忆（保留方向、类型与权重），
   组内互连关系随合并消失；LLM 规划的新关系只允许指向组内或原关联链上
   出现过的记忆，防止幻觉 ID。
5. **过滤已处理**：每处理完一条就把整组标记为已处理，后续节点跳过，
   直到全部整理完成；`--max-nodes` 限制单批处理量并在报告中给出剩余数量。
6. **低质量遗忘**：标题为空、摘要过短且重要性低、长期未用且重要性低的记忆
   会被归档（不再参与召回，但仍可在记忆页查看）。

合并与遗忘都走 Memory 既有的软删除（归档）语义，不会物理删除数据。

## 安全说明

- 整理会修改记忆库，请确认后再执行；`--dry-run` 不改动任何数据。
- 低质量判定刻意保守（多重条件同时满足才遗忘），避免误伤短但有用的记忆。
- LLM 的合并结果会做结构校验（`primary_id`、`forget_ids`、关联目标必须在
  给定范围内），非法输出自动退化为规则整理。
- 与天工同时运行时本进程为 Follower，所有读写经 IPC 转发给 Leader。
