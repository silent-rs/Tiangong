# 15. 记忆深度整理工具（tiangong-memory-consolidator）

对长期积累的记忆库做一次全量「深刻整理」：合并高度一致的记忆、重新归纳分类、
重建关联链，并遗忘低质量记忆。

工具是**独立制品**，位于 `plugins/tiangong-plugin-memory/consolidator/`：只通过
`tiangong-memory` 的公开 API（`MemoryHandle`）读写记忆，不修改 Memory 插件本身
的任何代码；接入方式与 sidecar 通用模式一致（竞争 Leader，天工运行时以
Follower 经 IPC 转发），因此天工正在使用时也可以安全运行，记忆数据始终只有一份。

## 使用

只需要指定天工根目录，工具会自动识别 Memory 系统配置的模型
（LLM / Embedding / Rerank，读取 `<根目录>/data/memory/config.json` 与
`<根目录>/models.json`）：

```bash
cargo run -p tiangong-memory-consolidator -- --root ~/.tiangong
```

| 参数 | 说明 | 缺省 |
|---|---|---|
| `--root <目录>` | 天工根目录（存储根），也可用环境变量 `TIANGONG_STORAGE_ROOT` | `~/.tiangong` |
| `--threshold <0~1>` | similar 相似召回阈值：达到即送 LLM 判定（只决定送审范围） | `0.90` |
| `--batch-size <n>` | similar：单次 LLM 判定最多包含的记忆数（含种子） | `20` |
| `--stage <阶段>` | 只执行指定阶段：`dedup` / `entity` / `distill` / `similar`，可重复或逗号分隔 | 全部 |
| `--max-llm-calls <n>` | 每个阶段最多调用多少次 LLM，`0` 表示不限 | `0` |
| `--distill-batch-size <n>` | distill：每次 LLM 调用最多包含的工具日志数 | `40` |
| `--distill-window-minutes <n>` | distill：相邻工具日志间隔超过该分钟数即切分时间段 | `30` |
| `--concurrency <n>` | LLM 并发请求数：判定并发进行，落库仍按顺序串行（受模型服务限流约束） | `4` |
| `--journal <文件>` | 执行记录（JSON Lines）路径 | `<根目录>/data/memory-consolidation/<时间>-<阶段>[-dry-run]-<pid>.jsonl` |
| `--max-nodes <n>` | similar：最多以多少条记忆为种子处理，`0` 表示不限 | `0` |
| `--offset <n>` | 跳过最新的 N 条再开始（断点续跑） | `0` |
| `--dry-run` | 试运行：只报告不落库（仍会调用 LLM 生成预览决策） | 关 |
| `--keep-low-quality` | 保留低质量记忆，不执行遗忘 | 关 |

建议第一次先用 `--dry-run` 预览将要发生的合并与遗忘，确认后再正式执行。

## 执行记录

每次运行（含试运行）都会写一个 JSON Lines 执行记录，启动和结束时打印路径。
每条删除、改写、新建记忆、关联变更以及每次 LLM 判定（完整送审内容与原始输出）
都在**执行前**追加一行并立即落盘（`sync_data`）；被删除的记忆保存完整快照
（全部字段、删除前的关联、证据路径），可据此追溯或人工恢复。记录写入失败即
中断整理——没有记录就不删除。结束行 `run_end` 含完整报告（终端只显示前 200 条
明细）。记录放在 `data/memory` 之外，不受 Memory 迁移/恢复影响。

| event | 内容 |
|---|---|
| `run_start` | 命令行参数、阶段、阈值、模型 |
| `llm_decision` | 送审内容 `prompt` 与 LLM 原始判定 `response` |
| `delete_node` | 被删记忆完整快照 `node`、`relations`、`evidence_path`、`reason`、`merged_into` |
| `update_node` / `create_node` | 改写前 `before`、写入内容 `after`、新建记忆 `id` |
| `upsert_relation` / `delete_relation` | 关联内容 |
| `run_end` | 致命错误、LLM 调用数、完整报告 |

## 整理阶段

整理分四个阶段，缺省按 dedup → entity → distill → similar 顺序全部执行；可用
`--stage`（可重复或逗号分隔）只执行部分阶段。试运行时后面的阶段会跳过前面
阶段「模拟删除」的记忆，统计与真实执行一致。建议分阶段执行：

```bash
# 1. 摘要完全一致的归一（不调用 LLM）
tiangong-memory-consolidator --stage dedup --dry-run
# 2. 工具日志提炼（先小批试跑）
tiangong-memory-consolidator --stage distill --dry-run --max-llm-calls 5
# 3. 相似召回 + LLM 判定
tiangong-memory-consolidator --stage similar --dry-run --max-llm-calls 5
```

- **dedup**：摘要完全一致（去空白、忽略大小写）的记忆直接归一（跨工作区），
  不调用 LLM。主记忆优先取「决策」类，其次重要性、使用次数、更新
  时间；标题取组内出现次数最多的；重要性取组内最高；组员的关联全部改挂到主
  记忆（重复关联取较大权重）后物理删除组员。摘要短于 20 字的不处理；证据类
  记忆还要求证据路径一致；工具日志留给 distill。
- **entity**：名称相同（忽略大小写与空白）的实体跨工作区分组，交给 LLM 合并
  描述（大组按 30 条分批，后一批以上一批的合并结果打头），组员关联改挂到主
  记忆后删除；同名但确属不同事物时由 LLM 拆分或保留。
- **distill**：工具日志（标题形如 `fs__file_write 产物`、即 `^[A-Za-z0-9_]+ 产物$`
  的证据类记忆）单条信息量很低。按工作区、按时间段（相邻日志间隔超过
  `--distill-window-minutes`，默认 30 分钟即切段）分批（每批最多
  `--distill-batch-size`，默认 40 条），连同证据文件路径和同时段的经历/决策
  记忆交给 LLM：提炼出新经历（`learned_from` 关联到保留的依据日志，`related_to`
  关联到相关上下文），并判定哪些日志可以删除。**先写新经历再删日志**，被删
  日志的关联改挂到新经历；LLM 没有点名删除的日志一律保留。证据路径经 Memory
  的只读接口 `evidence_paths` 读取，不计入使用次数。
- **similar**：相似召回 + LLM 统一判定（见下节），排除工具日志。

整理一律跨工作区：召回不按工作区过滤，同一内容在多个工作区各存一份只是重复。
similar 的 LLM 提示也允许跨工作区合并，只有记忆描述的是不同项目各自特有的事实时
才保留。

**并发**：entity 不同名称的组之间并发（组内多批顺序执行）；distill 各时间段批次
并发、按批次顺序落库；similar 同时在途的批次两两不共享记忆，结果返回后逐批落库，
被在途批次占用的种子推迟到释放后再组批。写入始终只有一个 Leader、按顺序执行，
执行记录与落库顺序一致。遇到限流（429）时调低 `--concurrency`。

`--max-llm-calls` 对 entity、distill 与 similar 分别计算。只执行 dedup 时不要求配置
LLM，也不读取/补写向量。

## similar 阶段

1. **获取所有记忆**：全库拉取活跃记忆（按更新时间从新到旧），排除工具日志与
   前置阶段已删除的记忆；无向量库时每批最多 5000 条，可用 `--offset` 断点续跑。
2. **相似召回**：读 LanceDB 已有向量做**全量精确余弦**（多线程，2 万条约 10 秒），
   所有达到 `--threshold`（默认 0.90）的相似对都保留，不截断；没有向量库时退化
   为「经 Memory 召回 + 字符二元组相似度」。**阈值只决定送审范围，不决定是否合并。**
   种子按相似记忆数从多到少排序。
3. **LLM 统一判定**：种子与全部尚未一起判定过的相似记忆分批（`--batch-size`，
   默认 20）交给 LLM，LLM 在一批中给出多个合并组、删除、重分类和新关联；未被
   点名的记忆保持原样。工具校验输出：只接受本批 ID、组间不重叠、每组至少两条。
   请求失败按间隔重试（默认 3 次、间隔 3 秒），重试耗尽即**中断整理并以非零码
   退出**。
4. **关联链重建**：被合并记忆的关系先改挂到主记忆（保留方向、类型，重复关联取
   较大权重），再物理删除组员；LLM 规划的新关系端点只允许是本批记忆或原关联链上
   出现过的记忆，防止幻觉 ID。
5. **避免重复送审**：同一对记忆只判定一次；合并后主记忆继承组员的相似记忆，出现
   未判定的新候选时重新排队。
6. **低质量遗忘**：标题为空、摘要过短且重要性低、长期未用且重要性低的记忆会被
   物理删除。

## 安全边界

- 整理会修改记忆库，`--dry-run` 不改动任何数据；合并与遗忘均为**物理删除**
  （经 Memory `delete_node` 移除记忆行、关联关系、全文与向量索引），删除后
  不可恢复，正式执行前请先审阅 `--dry-run` 的整理计划。
- 低质量判定刻意保守（多重条件同时满足才遗忘），避免误伤短但有用的记忆
  （如用户偏好）。
- LLM 输出做结构校验：`primary_id`、`forget_ids`、关联目标必须落在给定范围
  内，非法输出视为该次请求失败（计入重试与中断判定）。
- 与天工同时运行时本进程为 Follower，所有读写经 IPC 转发给 Leader（要求
  Leader 侧 Memory 同样包含 `delete_node` 能力）；本进程竞争到 Leader 时
  （天工未运行）在整理结束后自动释放租约。

## 代码位置

- `plugins/tiangong-plugin-memory/consolidator/src/main.rs`：CLI 与模型自动识别。
- `plugins/tiangong-plugin-memory/consolidator/src/consolidation.rs`：阶段编排与 similar 阶段。
- `plugins/tiangong-plugin-memory/consolidator/src/stages.rs`：dedup 与 distill 阶段。
- `plugins/tiangong-plugin-memory/consolidator/tests/consolidation_integration.rs`：
  端到端测试（合并、关联重建、低质量遗忘、试运行、批次上限、dedup 归一、
  distill 提炼与中断、跨阶段试运行）。
