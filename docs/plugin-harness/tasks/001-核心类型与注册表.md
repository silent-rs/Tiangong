# T001 - Slot/Seam/Contribution 核心类型与注册表

## 目标

建立「能力接缝 + 挂载点 + 贡献声明」的核心数据模型，以及 Slot Registry、Seam Hub 两个注册表骨架，作为后续所有任务的类型与路由基础。

## 范围

- 后端：`crates/plugin/tiangong-plugin-runtime/src/` 新增 Slot/Seam/Contribution 类型定义，以及 Slot Registry、Seam Hub（可新增 `slots.rs`、`seams.rs`，或并入 `registry.rs`）。
- 前端：`frontend/src/api/tauri.ts` 新增与后端对齐的 TS 类型（SlotId、SeamKind、UiContribution 等）。

## 依赖

- 前置任务：无。
- 后续任务：T002（Manifest 解析）、T003（桥接命令层）、T006（沙箱容器）都依赖本任务的类型。
- 可并行任务：无（本任务是类型根基）。
- 阻塞说明：T002/T003/T004/T006 都需要引用本任务定义的 Slot/Seam/Contribution 类型，未完成前不能开工。

## 任务

- [ ] 定义 Slot 分类与 ID 常量：`session.*`、`extension.*`、`sidebar.*`、`settings.*`、`global.*`，覆盖设计文档 6.1 的完整 Slot 目录。
- [ ] 定义 `UiContribution` 结构：`slot`、`id`、`title`、`icon`、`entry`、`open_mode`（`singleton`/`multi`）、`context`、`sandbox`。
- [ ] 定义 `SeamKind` 枚举：`Tool`/`Prompt`/`Lifecycle`/`Ui`/`Approval`/`Interaction`/`Event`/`Storage`。
- [ ] 实现 Slot Registry：登记合法 Slot，提供「是否为合法 Slot」「按前缀查询」能力，未知 Slot 返回明确错误。
- [ ] 实现 Seam Hub 骨架：`register`/`lookup`/`route` 占位接口（route 可先返回「未实现」，但接口要定型）。
- [ ] 前端 TS 类型与后端对齐，含序列化字段名（snake_case 对齐）。

## 不做

- 不实现 manifest 解析与校验（T002）。
- 不实现 Host Bridge 命令（T003）。
- 不实现任何 UI 容器的实际渲染（T006）。
- 不在 Seam Hub 里写具体路由逻辑（审批/交互路由后续任务做）。

## 验收

- `cargo check` 通过，类型与注册表可编译。
- Slot Registry 能对合法/非法 Slot ID 给出正确判定。
- Seam Hub 可完成一次 register → lookup 往返。
- 前端 TS 类型可通过 `tsc` 类型检查。

## 验证

- `cargo check -p tiangong-plugin-runtime`
- `yarn --cwd frontend build`（或 `yarn --cwd frontend tsc --noEmit`）
- 为 Slot Registry 补充单元测试：合法 ID 通过、非法 ID 报错、前缀查询正确。
